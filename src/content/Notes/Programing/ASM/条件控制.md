# 条件控制
## 标准 if else

```assembly
IF_BEGIN:
	逻辑判断
	jxx ELSE_BEGIN
	...
	jmp END
IF_END:
ELSE_BEGIN:
	...
ELSE_END:
END:
```
> 三目运算符 同理
> 逻辑判断与源代码相反(满足则跳过/不执行)


> [!NOTE]
> `IF_END` 与 `ELSE_BEGIN` 是同一位置

## 多分支 else if

```assembly
IF_BEGIN:
	条件判断
	jxx ELSE_IF_1_BEGIN
	...
	jmp END
IF_END:
ELSE_IF_1_BEGIN:
	条件判断
	jxx ELSEIF_2_BEGIN
	...
	jmp END
ELSE_iF_1_END:
ELSE_IF_2_BEGIN:
	条件判断
	jxx ELSE_BEGIN
	...
	jmp END
ELSE_iF_2_END:
ELSE_BEGIN:
	...
ELSE_END
END:
```

1. 每个`else if`条件前必有`jmp`
2. `jmp` 跳转地址相同(条件控制的结束)
3. `else` 分支无条件判断

> if 判断含 bool 运算 同理


## switch

- 表达式结果先与 case 最小值相减得 `key`
- `key` 先与 `max - min` 比较, 大于则跳转 `default`
- 小于等于 3 分支, 类似 [if 判断](#标准%20if%20else)
- 大于 4 分支时且 key 相对连续, 生成完整地址表, 以 key 搜索
	- key 少量空缺时, 表对应处存储 `default` 地址
	- key 大量空缺时, 生成**辅助索引表** (byte 数组), 采用节省空间的**二级查找**
	- 不连续, **二分查找**

> [!IMPORTANT]
> 编译器根据 `case` 的数量和值分布的连续性, 在 **`if-else` 链 (少量分支)**、**跳转表 (密集分支)** 和 **二分查找 (稀疏分支)** 之间选择最高效实现方案
> 减去最小值和检查范围:`(key > max_key) -> default`是几乎所有实现方式的**前置公共步骤**, 用于规范化输入和快速过滤无效值, 是最明显的优化
