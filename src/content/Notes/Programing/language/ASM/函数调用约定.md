# 函数调用约定

函数调用约定定义了**函数调用过程中参数传递、栈帧管理和返回值传递的规则**，是二进制兼容性的关键

1. **参数传递顺序**：参数从左向右还是从右向左压栈
2. **栈清理责任**：由调用者或被调函数清理参数栈
3. **寄存器使用**：哪些寄存器用于参数传递和返回值
4. **名称修饰规则**：编译器如何生成函数符号名

## 主流调用约定


| 约定       | 参数顺序  | 栈清理方   | 寄存器参数 | 可变参数 | 典型应用               |
|------------|-----------|------------|------------|----------|------------------------|
| **cdecl**  | 右→左     | 调用者     | 无         | 支持     | C标准库，跨平台代码     |
| **stdcall**| 右→左     | 被调函数   | 无         | 不支持   | Windows API           |
| **fastcall**| 右→左     | 被调函数   | 2-4个      | 部分支持 | 性能敏感函数          |
| **thiscall**| 右→左     | 混合       | `this`指针 | 不支持   | C++成员函数           |
| **vectorcall**| 右→左    | 被调函数   | 6个SIMD    | 不支持   | SIMD计算函数          |
| **syscall**| 固定顺序  | 内核       | 专用寄存器 | 不支持   | 操作系统内核接口       |

### 1. cdecl (C Declaration)
- **参数传递**：从右向左压栈
- **栈清理**：**调用者**清理
- **寄存器使用**：EAX/AX/AL 存放返回值
- **可变参数**：支持
- **适用场景**：C语言默认约定，跨平台通用
- **名称修饰**：函数名前加下划线（`_func`）

```nasm
; 调用示例 (x86)
push d ; 最右参数先入栈
push c
push b
push a ; 最左参数最后入栈
call _func
add esp, 16 ; 调用者清理栈
```

### 2. stdcall (Standard Call)
- **参数传递**：从右向左压栈
- **栈清理**：**被调函数**清理（`ret n`指令）
- **寄存器使用**：EAX存放返回值
- **可变参数**：不支持
- **适用场景**：Windows API标准约定
- **名称修饰**：`_func@n`（n为参数字节数）

```nasm
; 调用示例 (x86)
push 3   ; 参数入栈
push 2
push 1
call _func@12  ; 函数内执行 ret 12
```

### 3. fastcall
- **参数传递**：
  - 较前参数通过寄存器传递（ECX/EDX x86；RCX/RDX/R8/R9 x64）
  - 剩余参数从右向左压栈
- **栈清理**：被调函数清理
- **寄存器使用**：
  - 参数寄存器：ECX/EDX (x86), RCX/RDX/R8/R9 (x64)
  - 返回值：EAX/RAX
- **可变参数**：部分支持（寄存器参数固定）
- **适用场景**：性能敏感函数
- **名称修饰**：`@func@n` (x86), 无修饰 (x64)

```nasm
; x86 示例
mov ecx, a  ; 第一个参数
mov edx, b  ; 第二个参数
push d      ; 剩余参数
push c
call @func@16
```

### 4. thiscall (C++成员函数)
- **参数传递**：
  - `this`指针：ECX (x86/MSVC), ESI (x86/GCC)
  - 其他参数从右向左压栈
- **栈清理**：调用者清理 (MSVC), 被调函数清理 (GCC)
- **寄存器使用**：
  - `this`指针：ECX (MSVC), ESI (GCC)
  - 返回值：EAX
- **可变参数**：不支持
- **名称修饰**：复杂名称重整（如`?func@Class@@QAEXH@Z`）

```nasm
; MSVC x86 示例
mov ecx, obj_ptr ; this指针
push 42          ; 参数
call ?func@Class@@QAEXH@Z
add esp, 4       ; 调用者清理
```

### 5. vectorcall (SIMD优化)
- **参数传递**：
  - 前6个SIMD参数：XMM0-XMM5
  - 前2个整型参数：RCX/RDX (x64), ECX/EDX (x86)
  - 剩余参数从右向左压栈
- **栈清理**：被调函数清理
- **返回值**：XMM0/浮点寄存器
- **适用场景**：SIMD向量计算密集型函数
- **编译器支持**：MSVC 2013+, Clang 3.6+, GCC 6+

```nasm
; x64 示例
vmovaps xmm0, [vec1]  ; 第一个向量参数
vmovaps xmm1, [vec2]  ; 第二个向量参数
call func
```

### 6. syscall (系统调用)
- **参数传递**：
  - x86：EAX（系统调用号），EBX/ECX/EDX/ESI/EDI（参数）
  - x64：RAX（系统调用号），RDI/RSI/RDX/R10/R8/R9（参数）
- **调用指令**：`syscall` (x64), `int 0x80`/`sysenter` (x86)
- **返回值**：EAX/RAX
- **特点**：不依赖栈空间，直接通过寄存器传递

```nasm
; Linux x64 系统调用 (write)
mov rax, 1     ; sys_write 编号
mov rdi, 1     ; fd = stdout
mov rsi, msg   ; buffer
mov rdx, len   ; length
syscall
```

## 跨平台/编译器差异

### 1. x86 vs x64 差异
| 约定       | x86参数寄存器 | x64参数寄存器          |
|------------|---------------|------------------------|
| fastcall   | ECX, EDX      | RCX, RDX, R8, R9      |
| vectorcall | 无            | XMM0-XMM5, RCX, RDX   |
| syscall    | EBX,ECX,EDX   | RDI,RSI,RDX,R10,R8,R9 |

### 2. 编译器实现差异
| 约定       | MSVC         | GCC                  | Clang |
| -------- | ------------ | -------------------- | ----- |
| thiscall | `this`在ECX   | `this`在栈（-fthiscall） | 同GCC  |
| fastcall | 前2参数：ECX,EDX | 前2参数：ECX,EDX         | 同GCC  |
| cdecl    | 调用者清理栈       | 调用者清理栈               | 同GCC  |

## 最佳实践

### 1. 约定选择指南
- **跨平台库**：使用 `cdecl`
- **Windows DLL**：使用 `stdcall` 或 `vectorcall`
- **C++成员函数**：使用编译器默认 `thiscall`
- **性能关键函数**：使用 `fastcall` 或 `vectorcall`
- **系统编程**：使用 `syscall`

### 2. 显式声明示例
```c
// 跨平台声明
#ifdef _WIN32
  #define API __declspec(dllexport) __stdcall
#else
  #define API __attribute__((visibility("default"))) 
#endif

// 向量计算函数
#ifdef _MSC_VER
  #define VECTORCALL __vectorcall
#else
  #define VECTORCALL __attribute__((vectorcall))
#endif

API float VECTORCALL simd_sum(__m128 a, __m128 b);
```

### 3. 重要注意事项
1. **可变参数函数必须使用cdecl**
   ```c
   // 正确
   int cdecl_func(int count, ...); 
   
   // 错误！stdcall不支持可变参数
   int stdcall_func(int count, ...);
   ```

2. **跨编译器调用需保证ABI兼容**
   ```c
   // MSVC和GCC混合调用时使用extern "C"
   #ifdef __cplusplus
   extern "C" {
   #endif
     __declspec(dllexport) void __stdcall cross_compiler_func();
   #ifdef __cplusplus
   }
   #endif
   ```

3. **调试调用约定问题**
   - 使用反汇编检查参数传递顺序
   - 检查栈指针变化（清理不一致导致崩溃）
   - 使用`__builtin_return_address(0)`调试栈帧
